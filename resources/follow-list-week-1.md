## Observation Notes

### 1. Course And Community: ETHPanda / LXDAO

These accounts help me understand how a Chinese-speaking Ethereum builder community is organized. The trend I want to observe is how education, public goods, and proof-of-work style learning can help new builders move from reading to shipping. This connects to Week 1 because my repo, daily logs, and task proofs are also a small public learning trail. I still want to understand how community tasks become long-term project contributions.

### 2. Ethereum Protocol: Vitalik / Tim Beiko / Dankrad

These accounts are useful for following Ethereum roadmap discussions beyond surface-level token news. The core trend is that Ethereum development depends on protocol research, client coordination, scaling tradeoffs, and social consensus. This connects to Week 1 topics such as account models, signatures, transactions, networks, and smart contracts. I still need to build more background in L2, data availability, and account abstraction details.

### 3. AI Agent Stack: OpenAI / Anthropic / LangChain / Nous Research

These accounts help me track how AI agents are moving from chatbots toward tool-using workflows. The trend I want to observe is whether agents become more reliable through better tools, guardrails, tracing, memory, and evaluation rather than just stronger base models. This connects to Week 1 because my Learning Agent helped prepare notes, checklists, and safe Web3 workflows, but wallet confirmation stayed human-controlled. I still need to learn how to evaluate agent output more systematically.

### 4. Security And Wallet UX: OpenZeppelin / MetaMask / Safe

These accounts help me watch the security side of AI x Web3. The trend is that better contracts, better wallet warnings, and better account permission systems are all needed before AI agents can safely interact with on-chain systems. This connects to Week 1 because private keys, seed phrases, signatures, approvals, smart accounts, and multisigs were recurring safety themes. I still need to learn how to read contract permissions and token approvals more confidently.

### 5. Developer Tools: Remix / Foundry

These accounts help me follow the tools used to write, test, deploy, and debug smart contracts. The product trend is that Web3 tooling needs to lower the beginner barrier while still making security and verification visible. This connects directly to Week 1 because I used Remix to deploy and call a minimal `MinimalStorage` contract on Sepolia. I still need to practice moving from browser-based Remix experiments to local test suites with Foundry or Hardhat.

## How I Will Use This List

- Check 2-3 categories each week instead of scrolling randomly.
- Save high-quality posts that explain a concept, risk, tool, or real builder workflow.
